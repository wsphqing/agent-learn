# 第 1 章 · 为什么需要 Docker

> 本章目标：建立对 Docker 的**直觉**。不急着敲命令，先想明白"它到底解决了什么问题"，后面所有概念才有根。

---

## 1.1 一句话通俗解释：Docker 是什么

> **Docker 就是"集装箱 + 标准化码头"。**

在集装箱发明之前，货物（散装的箱子、桶、麻袋）要装船，得靠工人一件件搬，不同形状的货物摆放方式都不一样，装卸慢、易损坏、换条船又得重来。

集装箱统一了规格：**不管里面装的是家具还是香蕉，箱子外形都一样**。于是码头的吊机、卡车、货轮只要认这个标准箱子就行，装卸飞快，还能无缝换运输工具。

Docker 干的是同一件事，只不过对象是**软件**：

- 你的应用 + 它需要的一切（Node 版本、系统库、环境变量、配置……）被打包进一个标准化的"集装箱"（**容器**）。
- 任何装了 Docker 的机器（你的 Mac、同事的 Windows、云服务器上的 Linux）都能原样运行这个箱子，**不用关心箱子里面装的是什么技术栈**。

---

## 1.2 它到底解决了什么问题

### 问题一：「在我电脑上明明是好的啊」

这句话是所有开发团队的噩梦。你本地跑得好好的项目，一到同事电脑或服务器上就崩，原因通常是：

- Node 版本不一样（你 20，服务器 16）
- 少装了某个系统库（本地早就装过忘了）
- 环境变量、配置文件路径不一致
- 操作系统不同（你 macOS，服务器 Linux）

**Docker 的解法**：把"能跑起来的那套完整环境"整个装进镜像。别人不是"照着你的步骤重装一遍"（容易漏），而是**直接运行你打包好的那个环境**。环境一致了，"在我电脑上是好的"就变成了"在哪都是好的"。

### 问题二：装环境太痛苦

想在本地起一个 Postgres + Redis 来开发？传统做法要去官网下载、安装、配置、改配置文件、设开机启动……装完可能还和你之前装的另一个版本冲突。

**Docker 的解法**：

```bash
docker run -d --name pg -e POSTGRES_PASSWORD=secret postgres:16   # ← 一行，起一个 Postgres
docker run -d --name redis redis:7                                # ← 一行，起一个 Redis
```

想删掉？`docker rm -f pg redis` 一行清空，不在你系统里留任何垃圾。**用完即走，干净利落。**

### 问题三：一台机器上跑多个项目会打架

项目 A 要 Node 16，项目 B 要 Node 20；项目 A 用 MySQL 5.7，项目 B 用 MySQL 8。装在同一台机器上互相冲突。

**Docker 的解法**：每个项目跑在自己的容器里，**互相隔离**，各用各的版本，井水不犯河水。

## 1.3 ⚠️ 核心对比：Docker vs 虚拟机（VM）

这是最需要讲清楚的一点。你可能听过"Docker 是轻量级虚拟机"——这句话**方向对，但本质错**，容易误导。

先看两张结构图：

**虚拟机（VM）的结构：**
```
┌─────────┐ ┌─────────┐ ┌─────────┐
│  App A  │ │  App B  │ │  App C  │
├─────────┤ ├─────────┤ ├─────────┤
│ 完整 OS  │ │ 完整 OS  │ │ 完整 OS  │  ← 每个 VM 都装了一整个操作系统（几个 GB）
├─────────┴─┴─────────┴─┴─────────┤
│         Hypervisor（虚拟层）        │
├─────────────────────────────────┤
│           宿主机操作系统            │
└─────────────────────────────────┘
```

**Docker 容器的结构：**
```
┌─────────┐ ┌─────────┐ ┌─────────┐
│  App A  │ │  App B  │ │  App C  │
├─────────┴─┴─────────┴─┴─────────┤
│         Docker 引擎               │  ← 容器【共享】宿主机内核，不各带一个 OS
├─────────────────────────────────┤
│      宿主机操作系统（内核）          │
└─────────────────────────────────┘
```

**关键区别**：虚拟机每个都背着一整个操作系统；容器**共享宿主机的内核**，只打包应用和它依赖的那点用户态文件。所以容器是"轻"在这里。

### 对比表

| 维度 | 虚拟机（VM） | Docker 容器 |
|------|-------------|-------------|
| **隔离级别** | 硬件级，最彻底 | 进程级，够用 |
| **是否自带完整 OS** | ✅ 每个都带 | ❌ 共享宿主机内核 |
| **体积** | 几个 GB | 几十~几百 MB |
| **启动速度** | 分钟级（要开机） | 秒级 / 毫秒级（就是起个进程） |
| **性能损耗** | 较大 | 接近原生 |
| **一台机器能跑几个** | 几个~十几个 | 几十~上百个 |
| **本质** | 模拟一台完整的电脑 | 在共享内核上隔离运行一组进程 |

> 💡 **一句话记忆**：VM 是"在你电脑里再买一台完整的电脑"；Docker 是"在同一台电脑里给每个应用隔出一个独立房间，但共用一套地基（内核）"。
>
> ⚠️ 也正因为共享内核，**Linux 容器需要 Linux 内核**。macOS/Windows 没有 Linux 内核，所以 Docker Desktop 才偷偷起了个 Linux 虚拟机来提供内核（这就是第 0 章说的那个隐藏 VM）。容器跑在那个 VM 里，但每个容器本身仍然是轻量的。

## 1.4 核心概念全景图

Docker 的世界主要就四个词，先混个脸熟，后面各章展开：

```
   Dockerfile  ──build──▶  镜像(Image)  ──run──▶  容器(Container)
   （构建说明书）           （打包好的模板）        （运行中的实例）
                              │  ▲
                         push │  │ pull
                              ▼  │
                        镜像仓库(Registry)
                        比如 Docker Hub
```

- **Dockerfile**：一份文本"说明书"，写明"怎么把我的应用打包成镜像"。
- **镜像（Image）**：按说明书打包出来的**只读模板**，包含应用 + 完整运行环境。像"菜谱做好后拍下的标准成品照 + 配方"。
- **容器（Container）**：镜像"跑起来"的实例。像照着配方**真正做出来的那盘菜**。一个镜像可以起很多个容器。
- **镜像仓库（Registry）**：存放镜像的地方，方便分享和分发。**Docker Hub** 是官方公共仓库，类似代码界的 GitHub。

这张图就是 Docker 的主线，后面每一章都是在填充它的某个环节。

## 1.5 用你熟悉的方式理解

你有 Node 和 Go 背景，用类比会秒懂：

| 你熟悉的 | 对应的 Docker 概念 | 说明 |
|---------|------------------|------|
| `package.json` / `go.mod` | **Dockerfile** | 都是"声明式地描述依赖和构建" |
| `npm install` 后的 `node_modules` | **镜像** | 把依赖"固化"下来的产物 |
| `npm start` 跑起来的进程 | **容器** | 产物真正运行起来的实例 |
| npm registry / Go module proxy | **Docker Hub** | 集中存放、供全世界拉取 |
| `.gitignore` | **`.dockerignore`** | 声明哪些文件不参与打包 |

所以：**Docker 之于"整个运行环境"，就像 npm/go mod 之于"代码依赖"**——都是把"能跑起来所需的一切"变得可声明、可复现、可分享。你早就会这套思维了，只是这次打包的对象从"依赖"升级成了"整个环境"。

## 1.6 🔨 跟着敲一遍：感受"隔离"与"秒级启动"

这个练习让你亲身体会容器的两个特性：**互相隔离** + **启动飞快**。

```bash
# 1. 起一个 Ubuntu 容器并进入它的命令行
docker run -it --rm ubuntu:22.04 bash
# 参数解释：
#   run          创建并启动容器
#   -it          -i 保持输入通道打开 + -t 分配一个终端，合起来就是"给我一个可交互的终端"
#   --rm         容器退出后【自动删除】，不留垃圾（练习场景很好用）
#   ubuntu:22.04 用的镜像（Ubuntu 22.04）
#   bash         容器启动后要运行的命令：进入 bash shell
```

进入后，你的命令行提示符会变成类似 `root@a1b2c3d4:/#`，**你现在就"在容器里面"了**。试试：

```bash
cat /etc/os-release      # ← 看系统信息，会显示 Ubuntu 22.04（即使你的 Mac 不是 Ubuntu！）
touch /tmp/hello.txt     # ← 在容器里创建一个文件
ls /tmp                  # ← 能看到 hello.txt
exit                     # ← 退出容器。因为加了 --rm，这个容器连同里面的文件会被销毁
```

**验证隔离性**——再起一个新容器看看刚才的文件在不在：

```bash
docker run -it --rm ubuntu:22.04 bash
ls /tmp                  # ← 空的！上个容器的 /tmp/hello.txt 不在这里
exit
```

**预期结果**：第二个容器里**看不到** `hello.txt`。这证明了**容器之间是隔离的**——一个容器里的改动不会影响另一个。同时你会发现，第二次 `docker run` 几乎是**瞬间**进入命令行的（镜像已在本地，启动就是起个进程），这就是"秒级启动"。

> ⚠️ **易错点**：`--rm` 会在容器退出时删除容器，**里面没持久化的数据也一起没了**。练习时很方便，但真实场景（比如数据库）绝不能这么用，否则数据全丢。数据怎么保住？第 5 章专门讲。

## ✅ 本章小结

- Docker 的本质是**软件界的集装箱**：把应用和它的整个运行环境标准化打包，做到"一次打包，到处运行"。
- 它解决三大痛点：**环境不一致**、**装环境痛苦**、**多项目版本冲突**。
- 和虚拟机的核心区别：容器**共享宿主机内核**，所以又小又快；VM 各带一个完整 OS，重而慢。
- 主线四概念：**Dockerfile → 镜像 → 容器**，加上存放镜像的**仓库**。
- 类比你已有的知识：Docker ≈ 把"整个环境"也变成像 npm 依赖那样**可声明、可复现、可分享**。
