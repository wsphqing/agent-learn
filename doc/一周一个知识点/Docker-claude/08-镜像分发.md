# 第 8 章 · 镜像分发：推送与拉取

> 本章目标：学会把本地构建的镜像推到仓库、在别处拉下来，并搞定 macOS（Apple Silicon）构建镜像部署到 Linux 服务器的多架构问题。

---

## 8.1 为什么需要"分发"

到现在，你的镜像只存在于**你自己这台 Mac 的本地**。但真实部署流程是：

> 在**本地或 CI** 构建镜像 → 推到**镜像仓库** → 云服务器从仓库**拉取** → 运行。

云服务器不可能访问你 Mac 的本地镜像，所以**必须经过一个中间的仓库**来中转。这就是"镜像分发"。

---

## 8.2 `docker tag`：给镜像打标签

镜像名由**仓库地址 + 命名空间 + 名字 + 标签**组成（回顾 2.5）。要推送到仓库前，得把镜像"命名"成符合仓库规范的完整名字。

```bash
# 假设你本地有 todo-backend:1.0，要推到 Docker Hub 上你的账号下（假设用户名 huaqing）
docker tag todo-backend:1.0 huaqing/todo-backend:1.0
#   docker tag <源镜像> <目标名字>
#   ★ tag 命令其实是"给同一个镜像再加一个名字"，不是复制。两个名字指向同一个镜像ID。

docker images | grep todo-backend
#   预期：能看到两行，todo-backend:1.0 和 huaqing/todo-backend:1.0，镜像ID相同
```

**命名规范**（推送前必须符合）：

```
[仓库地址/]命名空间/名字:标签
      可选      Docker Hub用户名

例：
huaqing/todo-backend:1.0                       # Docker Hub，用户 huaqing
ghcr.io/huaqing/todo-backend:1.0               # GitHub Container Registry
registry.mycompany.com/team/api:v1.2.3         # 私有仓库
```

---

## 8.3 推送到 Docker Hub：完整流程

**第 1 步：注册账号**
去 <https://hub.docker.com> 注册一个免费账号。

**第 2 步：登录**

```bash
docker login
#   会提示输入用户名和密码。登录凭证存在本地 ~/.docker/config.json
docker login -u 你的用户名     # ← 也可以直接指定用户名
```

⚠️ **安全提醒**：现在 Docker Hub 推荐用 **Access Token** 代替密码登录（在 Hub 网站的 Account Settings → Security 里生成）。密码登录逐渐被弃用，用 token 更安全，也能随时吊销。

**第 3 步：打标签并推送**

```bash
docker tag todo-backend:1.0 你的用户名/todo-backend:1.0    # 1. 命名成完整格式
docker push 你的用户名/todo-backend:1.0                    # 2. 推送上传
#   预期输出：会看到每一层逐个上传 "Pushing" 的进度，最后显示 digest 和 size
```

**第 4 步：验证——拉下来试试**

```bash
docker rmi 你的用户名/todo-backend:1.0      # 先删掉本地的，模拟"另一台机器"
docker pull 你的用户名/todo-backend:1.0     # 从仓库拉回来
#   预期：Pull complete，成功拉回
```

推 + 拉都成功，你就实现了**镜像的分发**。

---

## 8.4 私有仓库简述

Docker Hub 的公共仓库人人可拉，适合开源。公司内部代码用**私有仓库**：

| 仓库 | 说明 |
|------|------|
| **Docker Hub 私有仓库** | 免费账号可建 1 个私有仓库，适合个人小项目 |
| **GitHub Container Registry (ghcr.io)** | 和你 GitHub 项目绑定，CI 集成方便，个人免费额度大方 |
| **Harbor** | 开源自建的企业级私有仓库，公司内网常用 |
| **云厂商**（阿里云 ACR、腾讯云 TCR、AWS ECR 等） | 托管服务，和云资源打通 |

用法和 Docker Hub 一样，只是镜像名前缀不同（`ghcr.io/xxx`），然后 `docker login ghcr.io` 登录即可。**流程完全一样，换个地址而已。**

## 8.5 ⚠️ 重点坑：架构不匹配（Apple Silicon → Linux 服务器）

这是 **M 芯片 Mac 用户部署时几乎必踩的坑**。

**问题**：你的 Mac 是 **ARM64** 架构（M1/M2/M3/M4）。你 `docker build` 出来的镜像默认是 **linux/arm64** 的。而大多数云服务器是 **x86_64（AMD64）** 架构。把 ARM 镜像推到 x86 服务器上跑，会报错类似：

```
WARNING: The requested image's platform (linux/arm64) does not match the detected host platform (linux/amd64)
```
或者直接运行失败、`exec format error`。

**为什么会有这问题**：镜像里装的是**为特定 CPU 架构编译的二进制**，ARM 的二进制无法在 x86 上执行（反之亦然）。

**解法：多架构构建（buildx）**

用 `docker buildx` 构建一个**同时支持 amd64 和 arm64** 的多架构镜像：

```bash
# 1. 创建一个 buildx builder（如果还没有）
docker buildx create --name multiarch --use
#   --name multiarch 给这个构建器起名，--use 设为当前默认
docker buildx inspect --bootstrap     # 初始化它

# 2. 用 buildx 构建【多架构镜像】并直接推送（多架构镜像必须打包推送，不能只存本地）
docker buildx build \
  --platform linux/amd64,linux/arm64 \
  -t 你的用户名/todo-backend:1.0 \
  --push \
  ./backend
#   --platform linux/amd64,linux/arm64  同时为两种架构构建 ★
#   --push                              构建完直接推送到仓库（多架构不能留在本地）
```

推到仓库后，这个标签下**同时存在 amd64 和 arm64 两份**。之后无论在 M 芯片 Mac（拉 arm64）还是 x86 服务器（拉 amd64），`docker pull` 都会**自动选择匹配的架构**，无缝运行。

⚠️ 补充：

- 多架构构建**比单架构慢**（要为每个平台都构建一遍，非原生平台靠 QEMU 模拟，更慢）。
- 只构建**不推送**的多架构镜像无法保存到本地（`--load` 只支持单平台）。所以多架构必须配 `--push`。
- 如果嫌麻烦，也可以在构建时**只指定目标平台**：`docker build --platform linux/amd64 -t xxx .`（构建一个纯 amd64 镜像，牺牲本地原生运行速度换兼容性）。

## 8.6 🔨 跟着敲一遍：把实战项目后端推到 Docker Hub

**前置**：有 Docker Hub 账号，把下面的 `你的用户名` 换成实际用户名。

```bash
# 1. 登录
docker login
#   输入用户名和密码/Token

# 2. 确保 backend 镜像存在（没有的话先构建）
docker build -t todo-backend:1.0 ./backend

# 3. 打上带用户名前缀的完整标签
docker tag todo-backend:1.0 你的用户名/todo-backend:1.0

# 4. 推送
docker push 你的用户名/todo-backend:1.0
```

✅ **预期输出**：一连串 `Pushing` 进度，最后：
```
1.0: digest: sha256:abc123... size: 1234
```
到 <https://hub.docker.com> 你的仓库列表里，能看到 `todo-backend` 这个仓库。

**验证跨机器可用（在本机模拟）**：
```bash
docker rmi 你的用户名/todo-backend:1.0    # 删除本地副本
docker run --rm 你的用户名/todo-backend:1.0 node -e "console.log('pulled from hub ✅')"
#   预期：从仓库拉取后运行，打印 "pulled from hub ✅"
```

**(M 芯片建议做一次)** 构建多架构镜像：
```bash
docker buildx create --name multiarch --use
docker buildx inspect --bootstrap
docker buildx build --platform linux/amd64,linux/arm64 \
  -t 你的用户名/todo-backend:1.0 --push ./backend
#   预期：为两个平台各构建一遍后推送成功
```

> 🎯 **自检**：如果你用 M 芯片 Mac 构建的镜像直接推到 x86 服务器，会发生什么？怎么解决？（答：架构不匹配，`exec format error`；用 `buildx --platform linux/amd64,linux/arm64 --push` 构建多架构镜像。）

---

## ✅ 本章小结

- 部署链路：**本地/CI 构建 → 推仓库 → 服务器拉取 → 运行**，仓库是中转站。
- `docker tag` 给镜像加符合仓库规范的完整名；`docker push` 上传，`docker pull` 下载。
- 仓库：Docker Hub（公共）、ghcr.io、Harbor、云厂商仓库，**用法一致只是前缀不同**。
- ⚠️ **M 芯片 Mac 的头号坑**：本地构建的是 arm64 镜像，x86 服务器跑不了。用 **`buildx --platform linux/amd64,linux/arm64 --push` 构建多架构镜像**解决。
- 登录凭证用 Access Token 比密码更安全。
