## 0.1 这份文档怎么用

这份文档的设计原则是**「读一段，敲一段」**。Docker 是一门手艺，光看不练，第二天就忘。所以：

- 每章末尾都有 🔨 **动手练习**，请一定亲手敲，并对照「预期输出」确认自己做对了。
- 遇到 ⚠️ 标记请放慢速度，这些都是新手最容易栽的坑。
- 命令里的注释（`# ←` 后面的内容）是重点，参数的含义都在那里。

建议每天学 1~2 小时、1 章左右，10 天走完。不要贪快，**概念 + 手感**两样都要。

## 0.3 贯穿全文的实战项目

我们会做一个经典的全栈 **Todo 应用**，它的结构是这样的：

```
todo-app/
├── backend/     # Node (Express) 写的后端 API
├── frontend/    # 前端页面（Vite 打包成静态文件）
└── 依赖的服务      # Postgres 数据库 + Redis 缓存
```

这个组合几乎覆盖了真实项目的所有容器化知识点：**编译型前端、Node 服务、有状态的数据库、需要网络互通的多个容器**。我们会随着章节一步步把它完善，最终部署上线。

> 你现在**不需要**真的有这个项目的代码。每章我会给出需要的最小代码片段，你跟着建文件即可。

## 0.4 环境准备：在 macOS 上安装 Docker Desktop

Docker 本身是 Linux 的技术。macOS 上并没有 Linux 内核，所以 **Docker Desktop 会在后台悄悄启动一个轻量级 Linux 虚拟机**，你的容器其实都跑在那个虚拟机里。你平时用 `docker` 命令感觉不到它的存在，但心里要有数（这解释了后面很多 macOS 专属的"坑"）。

### 安装步骤

1. 打开官网下载页：<https://www.docker.com/products/docker-desktop/>
2. ⚠️ **认准芯片架构**：
   - **Apple Silicon（M1/M2/M3/M4）** → 下载 **Apple Chip** 版本
   - Intel 芯片的老 Mac → 下载 **Intel Chip** 版本
   - 装错架构会导致性能极差甚至无法运行。查看你的芯片：点左上角  → 关于本机。
3. 双击 `.dmg`，把 Docker 拖进 Applications，打开它。
4. 首次启动会要求授权（输入登录密码），耐心等待右上角 🐳 鲸鱼图标变成**稳定不动**的状态（不再有动画），说明 Docker 引擎已就绪。

### 验证安装

打开终端，敲：

```bash
docker --version          # ← 查看 Docker 客户端版本，能打印版本号说明命令装上了
docker compose version    # ← 查看 Compose 版本（注意是 docker compose，中间空格，新版内置）
docker info               # ← 查看 Docker 引擎详细状态，能打印一大堆信息说明引擎在运行
```

**预期输出**（版本号可能不同）：

```
Docker version 27.x.x, build ...
Docker Compose version v2.x.x
```

如果 `docker info` 报错 `Cannot connect to the Docker daemon`，说明 **Docker Desktop 没启动**——去应用里打开它，等鲸鱼图标稳定。

> ⚠️ **易错点**：`docker` 命令能用 ≠ Docker 能工作。`docker --version` 只是问客户端；真正干活的是后台引擎（daemon）。引擎没起来，`docker run` 就会报"连不上 daemon"。记住：**先确认鲸鱼图标是稳定的**。

### （可选）配置镜像加速

国内网络从 Docker Hub 拉镜像可能很慢。可以在 Docker Desktop 设置里配置国内镜像源：

打开 Docker Desktop → 右上角 ⚙️ Settings → **Docker Engine**，在 JSON 里加一行 `registry-mirrors`：

```json
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io"
  ]
}
```

改完点 **Apply & Restart**。（镜像源地址会变动，若失效可搜索"Docker 国内镜像加速"找最新可用地址。）

## 0.5 🔨 跟着敲一遍：你的第一个容器

现在跑通经典的 `hello-world`：

```bash
docker run hello-world
```

**这一条命令背后发生了 5 件事**（理解它，你就理解了 Docker 的工作流）：

1. Docker 客户端把「运行 hello-world」的请求发给后台引擎。
2. 引擎在**本地**找 `hello-world` 镜像 → 没找到。
3. 于是自动从 **Docker Hub**（官方镜像仓库）**拉取（pull）** 这个镜像。
4. 用这个镜像**创建并启动一个容器**。
5. 容器里的程序打印一段欢迎文字，然后**运行结束、容器退出**。

**预期输出**（关键部分）：

```
Unable to find image 'hello-world:latest' locally      ← 本地没有，要去下载
latest: Pulling from library/hello-world               ← 正在从 Docker Hub 拉取
...
Hello from Docker!                                      ← ★ 看到这句就成功了！
This message shows that your installation appears to be working correctly.
...
```

只要看到 **`Hello from Docker!`**，恭喜，你的 Docker 环境完全 OK。

### 验证一下"容器已退出"

```bash
docker ps        # ← 列出【正在运行】的容器。此时应该是空的（hello-world 打印完就退出了）
docker ps -a     # ← 加 -a（all）列出【所有】容器，包括已退出的。能看到刚才那个 hello-world
```

`docker ps -a` 的**预期输出**里会有一行，`STATUS` 列显示类似 `Exited (0) 30 seconds ago`——`Exited (0)` 表示程序正常结束（0 是成功退出码）。

> 💡 这里你已经摸到一个重要事实：**容器不是"一直开着的虚拟机"，而是"运行一个进程"。进程结束，容器就退出了。** 这个直觉在第 2 章会反复用到。

### 收尾清理（可选）

```bash
docker rm $(docker ps -aq --filter ancestor=hello-world)  # ← 删掉刚才退出的 hello-world 容器
# 解释：docker ps -aq 只输出容器ID；--filter ancestor=hello-world 只筛由该镜像创建的容器；
#      docker rm 逐个删除这些容器。
```

## ✅ 本章小结

- Docker 在 macOS 上是**跑在一个隐藏的 Linux 虚拟机里**的，这点记住，能解释后面很多现象。
- 装好后靠**鲸鱼图标稳定** + `docker info` 不报错来确认引擎就绪。
- `docker run` 的完整流程：**本地找镜像 → 没有就去 Hub 拉 → 创建容器 → 运行 → 退出**。
- 容器的本质是**运行一个进程**，不是长开的虚拟机。
